# Reproduktions-Guide — Multi-Client SDR-Broadcast

*Stand: 17.05.2026.* Wie man das Ergebnis dieser Session von Null wieder
aufbaut: einen RTL-SDR-Stream von einem headless Raspberry Pi an mehrere
Clients gleichzeitig, live als Wasserfall in GNU Radio.

---

## Architektur in einem Satz

```
RTL-SDR → Pi (GNU Radio: osmosdr source → ZMQ PUB sink)
           → Tailnet →
        mehrere Clients (GNU Radio: ZMQ SUB source → Wasserfall)
```

**Warum es funktioniert:** ZMQ PUB/SUB ist von Natur aus one-to-many —
der Publisher sendet, beliebig viele Subscriber empfangen. Multi-Client
ist dadurch kein Problem, das man lösen muss, sondern existiert gar
nicht erst. (`rtl_tcp` ist dagegen single-client — nicht verwenden.)

## A. Raspberry Pi einrichten

### 1. Abhängigkeiten

Auf dem Pi installiert sein müssen: **GNU Radio**, **gr-osmosdr**,
**gr-zeromq**. Ohne die kann `sdr_zmq.py` nicht laufen (es importiert
`gnuradio` und `osmosdr`).

### 2. Streaming-Script

`~/sdr_zmq.py` — osmosdr source → ZMQ PUB sink auf `tcp://0.0.0.0:5000`.
Feste Parameter: **433.92 MHz**, **500 kS/s**, Gain **25**.
→ Datei liegt im Repo unter `[/pi/sdr_zmq.py](../pi/sdr_zmq.py)`.

### 3. systemd-Service

`/etc/systemd/system/sdr-zmq.service` — Boot-Start, `Restart=always`.
→ Datei im Repo unter `[/pi/systemd/sdr-zmq.service](../pi/systemd/sdr-zmq.service)`.

Aktivieren:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now sdr-zmq
```

### 4. Konflikte vermeiden — wichtig

Nur **ein** Programm darf den Dongle gleichzeitig halten. Läuft noch ein
alter SDR-Dienst, kommt `usb_claim_interface error -6`. Die obsoleten
Dienste deaktiviert lassen:

```bash
sudo systemctl disable --now sdr-fanout
```

(`sdr-fanout`, `sdr-relay.py`, `sdr-fanout.sh` sind überholt — sie würden
beim Boot mit `sdr-zmq` um den Dongle streiten.)

### 5. Netzwerk-Konfiguration

Das WiFi des Pi regelt `/etc/netplan/60-wifi.yaml`.

> ⚠️ Wurde mit REDACTED commited. Im Repo liegt nur die geblankte  
> Version `/pi/60-wifi.yaml.example`.
>
> Es muss also noch REDACTED mit der echten SSID und Passwort ersetzt werden!

## B. Tailscale

- Auf dem Pi **und** auf jedem Client installieren — und dem Tailnet
**beitreten**. "Installiert" ≠ "im Tailnet": Teammitglieder brauchen
eine Einladung in das Tailnet.
- Danach ist der Pi unter seiner Tailnet-IP erreichbar (in dieser
Session: `100.127.52.8`) — von überall, ohne Port-Forwarding.

---

## C. Client einrichten (pro Laptop)

1. **GNU Radio Companion** installieren.
  - macOS-Falle: `libgfortran`-rpath-Konflikt + fehlender
   `librtlsdr.2.dylib`-Symlink. Fix: rpath editieren, Binary neu  
   signieren, Symlink setzen. Siehe log fuer genaueren Bug und Loesung. 
2. **Flowgraph** bauen:
  - Block **ZMQ SUB Source**, Adresse `tcp://<pi-tailnet-ip>:5000`,
   Typ `complex`.
  - → Wasserfall-/Frequency-Sink dranhängen.
3. **Gain-Felder auf 0 lassen** — `osmosdr set_if_gain` segfaultet
  sonst (betrifft osmocom-/rtl_tcp-Clients).

## D. Funktionstest

Mehrere Clients gleichzeitig starten. Wenn alle denselben Wasserfall auf
433.92 MHz sehen → **reproduziert.** ✅

Wir haben ausserdem mit einem Keyfob Tastendruck getestet, ob dann ein Impuls im Wasserfalldiagram auftaucht. Hat geklappt.

## Parameter / Tuning


| Sample-Rate | Last pro Client | Hinweis                         |
| ----------- | --------------- | ------------------------------- |
| 250 kS/s    | ~2 MB/s         | leicht                          |
| 500 kS/s    | ~4 MB/s         | **bester Kompromiss (Default)** |
| 1 MS/s      | ~8 MB/s         | schwer                          |
| 2.4 MS/s    | —               | zu viel fürs WAN                |


3 Clients bei 500 kS/s ≈ 12 MB/s gesamt.

**Feste Abstimmung auf dem Pi; Clients sind reine Empfänger.** Retuning
(Web-UI / MQTT / REST) ließe sich später als **separater Kontrollkanal**
ergänzen, ohne das Streaming-Setup anzufassen — PUB/SUB-Streaming und
Steuerung sind unabhängig.

## Bekannte Stolpersteine (alle in dieser Session getroffen)


| Symptom                                    | Ursache & Fix                                             |
| ------------------------------------------ | --------------------------------------------------------- |
| GRC startet auf macOS nicht                | `libgfortran`-rpath + fehlender `librtlsdr`-Symlink       |
| Multi-Client crasht (`-11` / `0xC0000005`) | `rtl_tcp` ist single-client → ZMQ PUB/SUB nutzen          |
| Pi nicht erreichbar                        | Tailscale installiert, aber nicht dem Tailnet beigetreten |
| Segfault beim Start                        | `osmosdr set_if_gain` → Gain-Felder auf 0                 |
| `usb_claim_interface error -6`             | anderer SDR-Dienst hält den Dongle → erst stoppen         |
